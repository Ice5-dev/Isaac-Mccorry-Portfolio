01

Project Overworld

Independent project Aug 2026 — present In progress

Problem

The early idea is a spatial-computing concept centered on running and real-world competition. The immediate challenge was not to claim a finished product, but to reduce the concept to a first Solo Zone Challenge prototype and prepare a development environment that could support later experimentation.

Approach

Start with the technical foundation: define the prototype boundary, establish a Hermes-based workspace, verify basic local file operations, and connect a local language-model API before attempting a broader experience.

What I did

  • Defined the initial Solo Zone Challenge prototype scope.
  • Set up a Hermes-based development workspace.
  • Ran a smoke test for local file creation and retrieval.
  • Configured and verified a local API using Unsloth and Qwen2.5-Coder.

Evidence or artifact

The documented evidence covers the working setup and verification steps above. It does not yet establish a tested spatial experience, user results, or a completed feature set.

Lesson

A reliable environment is useful evidence, but it is only the start. The next meaningful proof must come from an observable prototype behavior and a repeatable test, not from the breadth of the concept.

Next step

Turn the Solo Zone Challenge scope into a small interaction that can be demonstrated, tested, and documented with screenshots, code, and explicit acceptance criteria.

02

Portfolio v2

Personal portfolio 2026 iteration Built

Problem

The original portfolio established the essential facts, but its single-card presentation did not yet show how decisions, evidence, incomplete work, and next steps relate.

Approach

Reframe the site as an editorial evidence record: preserve verified résumé facts, make project status visible at a glance, and give each featured project the same honest case-study structure.

What I did

  • Separated content, presentation, and interaction into maintainable files.
  • Designed a responsive espresso, ivory, and burnt-orange visual system.
  • Added keyboard, touch, wheel, and reduced-motion behavior.
  • Kept the original v1 available as a versioned starting point.

Evidence or artifact

This page is the artifact. Its source repository includes the design record, content-source notes, setup instructions, and production-ready static files.

Lesson

A strong visual identity can sharpen credibility only when labels and evidence make the work easier to interpret. Motion should help readers move through proof, never postpone access to it.

Next step

Add new work only when a public artifact or verifiable project record can support the case study. Prooflane remains unpublished here because no approved evidence was available for this build.
